# VISION — Chronos

> Зачем этот продукт существует

## Суть

Chronos — это AI-агент для поддержания целостности и консистентности документации в проектах. Следит за иерархией правды, ищет дубли, противоречия и устаревшие данные. Внутри — Пантеон из 5 специализированных агентов.

## Проблема

В каждом проекте рано или поздно возникает хаос в документации:

1. **Дублирование информации** — один и тот же факт описан в 3 разных документах по-разному
2. **Противоречия** — README говорит одно, ARCHITECTURE — другое, контракты — третье
3. **Устаревшие данные** — производные документы не обновлены после изменений канонических
4. **Потерянные документы** — файлы есть, но на них никто не ссылается
5. **Отсутствие обязательных документов** — для уровня L2 нужен REFERENCE.md, но его нет

Результат: разработчик не знает, чему верить. Новые сотрудники вводятся в заблуждение. Продукт теряет доверие.

## Решение

Пантеон из 5 AI-агентов, каждый со своей зоной ответственности:

```

│               ХРОНОС (Chronos)                  │
│            ГЛАВНЫЙ ОРКЕСТРАТОР                  │
├─────────────────────────────────────────────────┤
│                                                 │
│  ⏰ ХРОНОС (Chronos) — Хранитель Времени       │
│     Запускает циклы проверки.                   │
│     Определяет: пора ли в архив.                │
│     Его слово — закон для всех агентов.         │
│                                                 │
│  ⚖️ ЦЕНЗОР (Censor) — Страж Истины             │
│     Ищет противоречия и дубли.                  │
│     Сверяет факты с каноном.                    │
│                                                 │

```

## Целевая аудитория

### Кто будет использовать

| Сегмент | Потребность | Решение |
|---------|-------------|---------|
| **Solo-dev** | 1 проект, нет других агентов | Полный Пантеон |
| **Команда** | Много проектов, есть Sisyphus | Минимальная версия (Censor) |
| **DevOps** | CI/CD, автоматизация | JSON-отчёт + exit code |
| **Tech Writer** | Много документов, нужен порядок | Полный Пантеон + отчёты |

### Боли, которые закрываем

- "Я не знаю, какой документ актуален"
- "В README написано одно, в коде — другое"
- "Новые сотрудники смотрят устаревшие доки"
- "Много мусорных документов, непонятно что удалить"
- "Нет системы, каждый пишет как хочет"

## Ценность

### Для разработчика
- **Уверенность** — знаешь, что документы консистентны
- **Экономия времени** — не надо вручную сверять документы
- **Качество** — меньше ошибок в документации

### Для команды
- **Единый язык** — "Цензор нашёл ересь" вместо "тут противоречие"
- **Культура** — ритуалы и фразы создают командную идентичность
- **Процесс** — понятный порядок действий

### Для продукта
- **Доверие** — документация соответствует реальности
- **Масштабирование** — новые сотрудники быстрее включаются
- **Поддержка** — меньше вопросов "а как это работает?"

## Принципы

### 1. Иерархия правды
```
Contracts > Product Canon > Engineering Canon > Derived > Artifacts > Auxiliary
```
При противоречии документ верхнего уровня побеждает.

### 2. Один факт — одно место
Факт не должен дублироваться. Если дублируется — один документ ссылается на другой.

### 3. Производный обязан ссылаться на канон
Без ссылки на канон — документ не существует.

### 4. Время решает всё
Каждый документ имеет срок годности. Chronos определяет, пора ли в архив.

### 5. Модульность
Можно поставить только Censor. Или весь Пантеон. На выбор.

## Аналоги

| Инструмент | Что делает | Отличие от нас |
|------------|-----------|----------------|
| **markdownlint** | Проверяет стиль Markdown | Мы проверяем содержимое, не стиль |
| **alex** | Проверяет язык (деликатность) | Мы проверяем факты и ссылки |
| **remark-lint** | Линтер Markdown AST | Мы проверяем консистентность |
| **docusaurus** | Генерация документации | Мы проверяем существующую |
| **api-diff** | Сравнивает API версии | Мы сравниваем документы |

Наше уникальное отличие: **проверка консистентности между документами** с иерархией правды.
