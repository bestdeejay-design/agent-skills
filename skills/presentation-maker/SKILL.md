# Presentation Maker — конфигуратор презентаций

Загружай этот скилл когда нужно **создать презентацию из темы/промпта/контента**. Он повторяет пайплайн Presenton (проверенный код — схемы и промпты взяты из `presenton/presenton`), но выдаёт **самодостаточные результаты**: Markdown-аутлайн, HTML+CSS-слайды и реальный `.pptx`.

## Три выхода (всегда все три, если не попросили только один)

| # | Выход | Файл | Формат |
|---|-------|------|--------|
| 1 | Аутлайн | `outline.md` | структурированный план слайдов + выбор лейаутов + палитра |
| 2 | HTML-слайды | `slides.html` | автономный HTML, CSS 16:9, открывается в браузере |
| 3 | PPTX | `deck.pptx` | настоящий PowerPoint через `python-pptx` |

По умолчанию генерируются все три. Пользователь может попросить только один (`только html`, `только pptx`, `только аутлайн`).

## Пайплайн генерации

### Шаг 0. Собрать параметры (по умолчанию, если не указано)

| Параметр | По умолчанию | Диапазон |
|---|---|---|
| `n_slides` | auto-detect | 1–20 |
| `language` | ru (auto-detect из контента) | ru/en/auto |
| `tone` | «чёткий профессиональный» | варьируется |
| `verbosity` | standard | concise≈20 слов / standard≈40 / text-heavy≈60 |
| `include_title_slide` | true | true/false |
| `include_table_of_contents` | false | true/false |

Эти настройки **авторитетнее** просьб внутри контента/инструкций. Если в теме просят «другой язык/число слайдов» — побеждают явные параметры.

### Шаг 1. Сгенерировать аутлайн (структура слайдов)

Построй структуру как список слайдов, где **каждый слайд — это Markdown-контент** (то, что действительно увидит зритель), а не продп / команда для создания.

**Контент-рулы (критично, перенесено из Presenton):**
- Каждый слайд: `## Title` + содержимое (буллеты / сравнение / таблица / метрики).
- Объём: `~N слов` по verbosity (20/40/60). Меньше — лучше.
- Markdown, но **без `**bold**` и `__italic__`**.
- Первый слайд (титул): **только** title + имя выступающего + дата + обзор. Без лишнего.
- **Без URLs**, гиперссылок, цитат, ссылок, footer, списка источников.
- Данные **консистентны** между слайдами.
- Один слайд = одна цель. Перегруженная тема → разбить на несколько.
- Логический поток введение → заключение; без повторов и филлера.
- Если в контенте просят «slide 5: bar chart Q1 10, Q2 20» — в аутлайне пиши только таблицу `Quarter | Value` с числами, **без слов** «create a bar chart».
- Настоятельные факты, цифры, таблицы и код — включать, если есть.

**Иконки (критично):**
- **Запрещены эмодзи** в качестве иконок на слайдах (🎓🤝📊 и т.п.) — ни в контенте, ни в спеке, ни в аутлайне.
- Если слайду нужны иконки — **только SVG из популярных наборов** (Lucide/Feather и аналоги): файл `templates/icons/<name>.svg` в папке скилла.
- В спеке/аутлайне указывай **имя иконки без расширения** (`"icon": "graduation"`), сборщик сам подставит инлайн-SVG.
- Доступные иконки: `graduation`, `users`, `presentation`, `building`, `chart`, `family`, `bot`, `zap`, `briefcase`, `award`, `arrow-right`. Если нужной нет — добавить SVG-файл (Lucide-стиль: `stroke="currentColor"`, `stroke-width="2"`, viewBox `0 0 24 24`) в `templates/icons/`.

**Формат аутлайна в `presentation.md`:**
```markdown
# <Титул презентации (plain text)>  — via plain, не markdown

## Slide 1 — Title
- Титул: ...
- Имя: ...
- Дата: ...
- Обзор: ...

## Slide 2 — Problem
- Буллет 1
- Буллет 2

## Slide 3 — Data
| Quarter | Value |
|---|---|
| Q1 | 10 |
| Q2 | 20 |
```

### Шаг 2. Выбрать лейаут для каждого слайда (маппинг контент → лейаут)

Из извлечённой логики Presenton. Для каждого слайда выбери **тип лейата** и укажи его в аутлайне (`slide type: ...`).

| Контент / цель | Лейаут |
|---|---|---|
| Цель всей презентации или темы → Title/Opening, Closing → Title | `title` |
| Таблица с **текстовыми** данными | `table` |
| Таблица с **числовыми** данными | `chart` (n столбцов → n-1 графиков) или `metrics` |
| Сравнение/контраст двух+ вещей | `comparison` (side-by-side) |
| Процесс/workflow/этапы | `process` (визуальная пошаговая) |
| Понятие/идея (не данные) | `image` / `image+text` |
| Метрики/ключевые показатели | `metrics` |
| Оглавление (только если контент — оглавление) | `table_of_contents` |
| Открытие главы/раздела | `divider` |
| Вывод/заключение | `title` или `emphasis` |
| Ключевая мысль / вывод одним утверждением | `quote` |
| Один hero-показатель (гигантское число) | `big_number` |
| Набор возможностей (иконка+заголовок+описание) | `feature` (сетка фич) |
| Партнёры/бренды/заказчики списком | `logos` (сетка) |
| План/повестка в начале | `table_of_contents` |

### Выбор лучшего лейаута для следующего слайда

Сборщик умеет выбирать лейаут сам (`pick_layout` в `build_html.py`), если в спеке указать `"type": "auto"` или не указывать тип. Алгоритм идёт по приоритету контента:

1. Явный `type` в спеке — всегда побеждает.
2. `quote` → quote; `logos` → logos; `toc`/`table_of_contents` → table_of_contents; `features` → feature; `steps` → process.
3. `items` с title/desc → timeline.
4. `columns` → comparison; `metrics` → metrics.
5. `value` (hero-число) → big_number.
6. `table`: числовые столбцы (2+) → chart, текстовые → table.
7. `bullets`: если предыдущий слайд тоже bullets и буллеты **метрико-подобные** (содержат `:`, `%`, `млн`, `млрд`, `₽`) → kpi_row (разнообразие), иначе — bullets.

**Правила разнообразия:** автовыбор учитывает тип предыдущего слайда и избегает двух одинаковых подряд, когда есть лучшая визуальная альтернатива (bullets→kpi_row). При этом «лучший под смысл» важнее «разнообразия ради» — не искажай контент под лейаут.

**Правила выбора (критично):**
- Контент с таблицей → **обязан** выбрать `table` или `chart`-лейаут.
- Таблица с текстом → только `table`, не chart (chart только для чисел).
- Числовая таблица → `chart`, **не** `metrics` (метрики — для отдельных показателей, не для таблиц).
- Лейаут с картинкой — только если контент содержит картинку или пользователь явно просит изображение.
- **Соседние слайды должны быть разными** (кроме титульного повтора).
- Разнообразить: текст+визул, инфодензит.
- Допустимо использовать один лейаут несколько раз, если так лучше по смыслу.

### Шаг 3. Выбрать тему и сгенерировать палитру

**Темы (каждая = набор лейаутов + шрифтовая система):**

| Тема | Характер |
|---|---|
| `general` | минимальный, чистый, много воздуха |
| `modern` | современный, ровные карточки, большие скругления |
| `executive` | строгая, деловая, тёмная |
| `momentum` | динамичная, акценты |
| `swift` | Apple-style, воздух, бирюзовый |
| `standard` | базовый, универсальный |

Если тема явно не указана — `general` или `modern`.

**Извлечение палитры (аналог `ThemeData` из Presenton):**
Для каждой темы сформируй такие ключи:
```
primary / background / card / stroke /
background_text / primary_text /
graph_0..graph_4   (до 5 серий графов)
```
Рекомендация для светлой темы: `background: #FFFFFF`, `primary: #007AFF`-синий (или акцент по теме), тёмный текст `primary_text: #1C1C1E`. Для тёмной: `background: #1C1C1E`, текст светлый.

В аутлане обязательно выпиши выбранную палитру, чтобы HTML и PPTX использовали **одну и ту же** палитру.

## Дизайн-система (обязательно к соблюдению)

Шаблон `templates/slides.html` уже содержит полную дизайн-систему: токены пространства/типографики, хелпер-классы и эстетические режимы (`mood`). Палитра приходит в `:root`-переменные из темы, при этом **дизайн-токены шаблона сохраняются** (сборщик переопределяет только палитровые переменные). Соблюдай систему, а не подгоняй стили «под каждую презентацию».

### 5 принципов (критично)

1. **≤2 шрифтовых семейства, ≤3 начертания.** `--font` (основной, текст/UI) и опционально `--font-display` (заголовки/акценты). Не заводи новые семейства ради пары слайдов.
2. **≤4 акцентных цвета + 1 нейтральный фон.** Палитра = 1 primary, до 2–3 акцентов (светлый/тёмный), нейтрали (`background`, `card`, `stroke`, `text`, `muted`). Больше — шум.
3. **Одна цель на слайд, один фокус-объект.** Не смешивай метрику, таблицу и график без нужды. Взгляд зрителя должен упираться в якорь (заголовок/ключевая цифра), а не блуждать.
4. **Контраст текста WCAG ≥ 4.5:1 (текст) и ≥ 3:1 (крупный/акценты).** Светлый текст на тёмном фоне и наоборот. Проверяй глазами на финальном скриншоте.
5. **Thumbnail-тест и ритм.** Слайд должен читаться с расстояния вытянутой руки и в миниатюре: крупная иерархия, воздух, единые отступы.

### 5.2 Токены (в шаблоне, используй вместо хардкода)

- **Spacing** (4px-база): `--s-1:4px … --s-9:96px` — для отступов, gap, padding.
- **Type scale** (16:9, масштабируется по размеру слайда): `--t-display`, `--t-h1`, `--t-h2`, `--t-h3`, `--t-body`, `--t-meta`, `--t-caption`.
- **Радиусы**: `--radius`, `--radius-sm`, `--radius-lg`, `--radius-full`.
- **Тени**: `--shadow`, `--shadow-hover`, `--shadow-soft`.
- **Шрифты**: `--font`, `--font-display`, `--font-mono`.
- **Контраст**: переменные `--contrast-*` (прозрачность текста по иерархии).

### 5.3 Хелперы (в шаблоне, используй в лейаутах)

- `.eyebrow` / `.eyebrow--accent` — маленький надзаголовок-рубрикатор над `h1/h2`.
- `.kicker` — подзаголовок-лид после заголовка.
- `.mono` — моноширинный текст (числа, коды, метаданные).
- `.hairline` — волосяная линия-разделитель.
- `.duotone` — двухцветный градиентный заголовок (color-mix primary+bg).
- `.index-num` — крупный номер индекса/счётчик секции.

### 5.4 Эстетические режимы (`mood`) на `.deck`

Mood можно задать в `deck.json` (`"mood": ...`) или уже вшит в темы (см. `templates/themes/*.json`). Он переопределяет радиусы/тени/шрифтовую стилистику, не трогая основной палитры.

| mood | Характер | Когда использовать |
|---|---|---|
| `swiss` | минимализм, строгая сетка, волосяные линии, display-акценты | бизнес, стратегия, аналитика, «чисто и строго» |
| `editorial` | журнальная типографика, serif-display заголовки, дуо-градиенты | бренды, контент, креатив, премиум-сторителлинг |
| `flat` | ровные карточки, крупные радиусы, без теней, бенто | стартапы, продукт, современная лаконичность |
| `glass` | полупрозрачные карточки, blur, glow — Apple-стиль | tech-продукт, keynote-стиль, премиум UI |
| `dark` | тёмный блок, моноширинная индексация, консольная строгость | тех, код, data-анализ, ночной режим |

Правило mood: не смешивай 2+ режима в одной презентации; mood должен согласовываться со смыслом (не ставь светлый мягкий mood для тёмной палитры и наоборот).

## Продакт-дизайнер — расширенные требования к презентации

Модуль добавляет «продуктовый взгляд» на слайды поверх дизайн-системы. Это не эстетическая пожелательность, а **проверяемые требования**: итоговая дека проходит сводный чек-лист «Продакт-дизайнер» (внизу) до сдачи. Разделы: **нарратив/ИА**, **визуализация данных**, **доступность и типографика**, **премиум-ощущение**.

### A. Нарратив и информационная архитектура

**Дуги (по характеру контента):**
| Дугa | Когда | Схема |
|---|---|---|
| Problem→Solution→Proof→CTA | аудитория ещё не знакома с проблемой | боль → решение → доказательства → один призыв |
| Sparkline (Duarte) | нужно убедить / большая идея | чередование «что есть» ↔ «что могло бы быть» **на протяжении** презентации |
| STAR | доказать компетенцию кейсом | Situation→Task→Action→Result (один слайд = один кейс) |
| S.T.A.R. Moment | есть одна шокирующая цифра/поворот | один запоминающийся момент на всю деку |

**IA на слайде:**
- **Одна идея на слайд** — слайд отвечает на один вопрос; две независимые мысли → два слайда.
- **Заголовок = вывод, а не тема** (assertion headline): полное предложение с глаголом и утверждением («Рост выручки ускорился до 40% в Q3» вместо «Выручка»).
- **Пирамида (Minto)**: тезис сверху, под ним ≤3 опоры, каждая подкреплена фактами; опоры — MECE.
- **Прогрессивное раскрытие**: детали/данные не вываливаем на один слайд — сложное на отдельные слайды/приложение.

**Сторибординг:** setup→payoff (ранние детали «выстреливают» позже), foreshadowing (намёк на будущий вывод), правило трёх, сквозная линия (каждый слайд продвигает главную идею; лишний — удалить), логические переходы между слайдами.

**Консалтинг vs питч vs кинот:** консалтинг — пирамида + SCQA, плотные данные, assertion-заголовки, аудитория читает сама; питч — проблема/решение/рынок/тракция/команда/CTA, 10 минут, метрики; кинот — sparkline, эмоциональная дуга, минимум текста.

**Анти-паттерны:** slide-ument (слайд = документ), много буллетов, орфан-слайды, нет переходов, нет сквозной линии, заголовок-тема вместо вывода.

### 2. Визуализация данных

**Выбор типа (сначала сформулируй единственное сообщение слайда, потом тип):**
| Форма данных | Сообщение | Тип |
|---|---|---|
| Тренд во времени | «как меняется» | линия (не более 3–5 серий) |
| Ранжирование | «кто больше» | бары, отсортированные по убыванию |
| Доли до 100% | «как делится целое» | донут/пирог **только** при ≤5 долях; иначе stacked bar |
| Сравнение значений | «разница» | столбцы (или таблица) |
| Много точных значений / поиск строк | «посмотри на данные» | таблица |
| Одно число + контекст | «вот результат» | metric card (не график) |

**Чистые графики:** минимум сетки, прямые подписи вместо легенды, сортировка баров, максимум 2 знака после запятой (лучше 0–1), ось Y столбцов с 0, без 3D, единые шкалы при сравнении, без двойной оси.

**Metric card:** округли до 1–2 значащих цифр («12,4 млн» не «12 431 287»); префикс/суффикс единиц; дельта vs цель (▲/▼ +12% или 68% из 100%); контекстное сравнение; крупное число + мелкая подпись.

**Таблицы:** ≤5–7 столбцов и ≤8–12 строк; числа — вправо, текст — влево; зебра/тонкие линии; **подсвети ответ** (ключевая строка/ячейка выделена); первый столбец — человекочитаемый идентификатор.

**Честность (Tufte):** data-ink ratio (макс «чернил» на данные), сигнал vs шум, не обрезай ось столбцов, не подбирай базовую линию, подписывай единицы.

### 3. Доступность и типографика (WCAG)

- **Контраст (WCAG 2.1/2.2 AA):** обычный текст ≥4.5:1, крупный (≥18pt/24px или 14pt bold) ≥3:1. Для слайдов цель — AAA-запас (7:1 / 4.5:1): проектор «съедает» контраст. **Не округляй** — 4.49:1 == фейл.
- **Авто-палитра:** текст задаётся по фактическому фону (тёмный фон → near-white текст, светлый фон → near-black), контраст считается программно, а не «по красоте».
- **Не только цвет (1.4.1):** серии графика/статусы различаются не только цветом — есть паттерн/иконка/подпись.
- **Не-текст (1.4.11):** линии, сегменты, границы, состояния ≥3:1 против соседних цветов.
- **Типoграфика проекции (1080p):** заголовок ≥36–44px, тело ≥24–28px, подписи ≥18–20px; крупный x-height; длина строки 40–70 символов; межстрочный 1.3–1.5; тело не капсом.
- **Текст на «шумном» фоне:** непрозрачная плашка или скрим над фото/градиентом; обводка — только дополнение.
- **Читаемость:** правило 50/25/10 (≤50 слов — сложный, ≤25 — обычный, ≤10 — ключевой); без переносов и обрезки текста в контейнерах.

### 4. Премиум-ощущение (планка качества)

**Рычаги «дорого»:** пробел как роскошь (на слайде контент <60% площади), единые поля и сетка, сдержанная палитра (60-30-10: 60% фон, 30% текст/карточки, ≤10% акцент), типографическая иерархия из 3 уровней, один доминирующий элемент на слайд, единая иконография (одна толщина штриха), сдержанное движение.

**Сигналы «дёшево»:** всё по центру, клип-арт/стоковый вид, **эмодзи как иконки**, радужная палитра, чрезмерные тени, многословные слайды, несогласованное выравнивание, дефолтный стиль PPT.

**Дизайн-контракт (держать на каждом слайде):** одна позиция заголовка, один радиус карточек, одна толщина штриха иконок, один источник всех чисел, одна палитра/отступы/тень/переходы. Нарушение хотя бы на одном слайде — «собрано из кусков».

### Сводный чек-лист «Продакт-дизайнер» (пройти перед сдачей)

**Нарратив / ИА**
1. Каждый заголовок — assertion headline (вывод, а не тема).
2. Одна идея на слайд; нет двух несвязанных утверждений.
3. Слайд логически вытекает из предыдущего; все продвигают сквозную линию (нет орфанов).
4. Тело подтверждает заголовок; ≤3–5 буллетов, каждый — короткая фраза.
5. Есть сквозная линия (по заголовкам всех слайдов читается история) и CTA в конце.
6. Есть контраст «что есть / что могло бы быть» (для убедительных); есть один S.T.A.R. момент.

**Данные**
7. Каждый график/таблица/карточка имеют подпись-вывод (что видеть).
8. Ранжирование → бары по убыванию; столбцы → ось Y с 0; линия → ≤5 серий, без двойной оси.
9. Пирог/донут → только доли ≤100%, ≤5 долей, без 3D, подписи напрямую.
10. Числа ≤2 знака после запятой, с единицами; metric card округлена до 1–2 значащих цифр, есть дельта.
11. Таблица ≤7 столбцов / ≤12 строк; числа вправо, текст влево; ключевая строка/ячейка подсвечена; единицы подписаны.

**Доступность**
12. Контраст каждого текста ≥4.5:1 (крупный ≥3:1); не-текст ≥3:1; без грубой округляемой ошибки.
13. Тело ≥24px (1080p), длина строки 40–70, межстрочный 1.3–1.5; нет капса в теле.
14. Серии/статусы различаются не только цветом; текст над фото/градиентом — с подложкой.

**Премиум**
15. ≤1 стиль тени на всю деку; единый радиус карточек; заголовки на одной базовой линии.
16. Ни одного элемента ближе 40px к краю слайда; элементы на сетке (шаг ≥4px).
17. Палитра ≤3 ролей, акцент ≤10%; контент на слайде <60% площади; нет эмодзи-иконок.

## Верификация — ОБЯЗАТЕЛЬНЫЙ гейт перед сдачей

Слайды должны быть собраны **качественно, эстетично и лаконично**. Это не пожелание, а обязательный шаг: презентация не считается готовой, пока не пройдёт проверку.

### Шаг 1. Автоматическая проверка `verify_slides.py` (обязательно)

После сборки `slides.html` **обязательно** прогнать скрипт верификации в реальном браузере:

```bash
# из venv проекта, где установлен playwright:
.venv/bin/python ~/.config/opencode/skills/presentation-maker/scripts/verify_slides.py slides.html --spec deck.json
```

Скрипт открывает Chromium и для каждого слайда проверяет:
- заголовок и непустой контент;
- нет горизонтального переполнения самого слайда;
- **текст не вылезает за границы карточек** (metric/step/col/tl/kpi/bullet/table-row/badge);
- нет обрезанного текста (`scrollWidth > clientWidth`);
- навигация (стрелки) переключает слайды;
- число слайдов совпадает со спекой (`--spec`).

**Exit code 0 = PASS, 1 = FAIL.** Если FAIL — исправить и пересобрать. Сдавать презентацию с FAIL запрещено.

> Если `playwright` не установлен: `.venv/bin/pip install playwright && .venv/bin/playwright install chromium`

### Шаг 2. Визуальный контроль (обязательно)

Даже при PASS скрипта — открыть `slides.html` в браузере и глазами проверить эстетику:
- воздух и отступы: ничего не прилипает к краям слайда, заголовки не вплотную к карточкам;
- крупный шрифт в метриках/числах, минимум текста на слайде (лаконичность);
- единая палитра: карточки/акценты/прогресс-бар в цветах выбранной темы;
- длинные слова переносятся или ужимаются, а не вылезают из карточек;
- на соседних слайдах разные лейауты, нет визуального повтора.

Любая проблема — исправить в шаблоне/спеке и пересобрать, потом снова прогнать шаг 1.

### Шаг 3. Продакт-дизайн-ревью (обязательно)

Пройти **сводный чек-лист «Продакт-дизайнер»** (раздел «Продакт-дизайнер — расширенные требования»). Прогони его как ревьюер: для каждого из 17 пунктов проверь на реальных слайдах (заголовки, структура, таблицы/графики, контраст, отступы). Если хотя бы 1 пункт не проходит — исправить (контент/шаблон/спек) и пересобрать, затем повторить шаги 1–2. Презентация с непройденным чек-листом не сдаётся.

## Smoke-тест скилла (проверить после создания)

Когда скилл готов, прогнать 3 выхода с мини-темой, например «Презентация о сервисе UniverID», на 3-4 слайде. Удостовериться:
1. `presentation.md` — корректная структура, контент-рулы соблюдаются.
2. `slides.html` — открывается, слайды перелистываются, палитра применена.
3. `verify_slides.py` — PASS на готовой презентации (и FAIL на намеренно битой — проверить, что скрипт ловит переполнения).
4. `deck.pptx` — открывается в Presentёре без глюков.
