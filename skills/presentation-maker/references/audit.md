# deck_audit — aesthetic-quality gate

Механический эстетический гейт для спецификации деки (`deck.json`), дополняющий
*функциональную* проверку переполнения `deck-html/scripts/verify_slides.py`
(Chromium layout QA). `deck_audit.py` отвечает на вопрос «выглядит ли дека
цельно / не хуже ли она стала» детерминированно (exit 0/1), без браузера.

> **Borrowed from frontend-perfection.** WCAG-математика относительной яркости
> (`relative_luminance` / `contrast_ratio`) и идея сканирования токен-блока
> (`:root{...}`) реплицированы инлайн из `skills/frontend-perfection/scripts/meta_audit.py`.
> Runtime-зависимости на `frontend-perfection` нет — математика скопирована с
> комментарием-атрибуцией.

## Использование

```bash
python3 deck_audit.py deck.json [--html slides.html] [--out report.json]
```

- `deck.json` — обязателен. Читаются `theme.palette{...}`, `theme.mood`,
  `theme.graphs`, `slides[].type/title/bullets/body`, `strategy.density`.
- `--html slides.html` — опционально. Включает проверку `tokens:raw-hex` по
  реальному HTML (поиск «голого» hex вне `:root`). Без `--html` проверяется, что
  значения палитры в `deck.json` — валидный 6-значный hex.
- `--out report.json` — записать отчёт в файл (дублирует stdout).

## Контракт выхода

- **Exit 0** — нет ни одного `fail` (предупреждения `warn` разрешены).
- **Exit 1** — хотя бы один `fail`.
- **Exit 2** — ошибка использования / IO (файл не найден, битый JSON).

Отчёт — компактный JSON (как у `meta_audit.py`): массив `checks` с полями
`id`, `title`, `status` (`pass`/`warn`/`fail`), `detail`, и блок `summary`
в конце (`total` / `passed` / `warned` / `failed`). Детерминирован: один и тот
же вход → идентичный отчёт (порядок чеков фиксирован, без рандома).

## Чек-лист аудита

### `contrast:wcag` — WCAG-контраст палитровых пар
Считает отношение контраста через WCAG 2.x relative luminance для пар:

| Пара | Порог (AA) | Примечание |
|---|---|---|
| `primary_text` на `background` | ≥ 4.5:1 | обычный текст |
| `primary_text` на `card` | ≥ 4.5:1 | обычный текст |
| `background_text` (on_primary) на `primary` | ≥ 4.5:1 | текст на акценте |
| `muted` на `background` | ≥ 4.5:1 | вторичный текст |
| `graph_0..4` на `background` | ≥ 3:1 | не-текст (линии/сегменты графика) |

- **fail**, если любая пара ниже своего порога.
- **pass**, если все пары в норме.
- Stretch (AAA): 7:1 / 4.5:1 — указывается в `detail`, но не влияет на статус.
- Значения по умолчанию (при отсутствии ключа) совпадают с `build_html.py`.

**Фикс:** затемнить/осветлить текст или фон до нужного отношения; для графиков
брать цвета контрастнее фона. Не округлять в меньшую сторону (4.49 == fail).

### `tokens:raw-hex` — нет «голого» hex вне токен-блока
- С `--html`: любой `#hex` вне блока `:root{...}` (и не из `SHADOW_GREYS`
  `#000`/`#fff`) — **fail**. Все цвета должны жить в токенах (правило
  дизайн-системы: «zero raw hex outside the token block»).
- Без `--html`: каждое значение палитры должно быть валидным 6-значным hex —
  иначе **fail**.

**Фикс:** вынести цвет в CSS-переменную в `:root`; в `deck.json` писать только
через `theme.palette`.

### `palette:roles` — бюджет акцентов (≤4)
Акцентные роли = `primary` + `graph_0..4`. Считаются **различные** (без учёта
регистра) цвета.
- **warn**, если > 4 различных акцентов (шум в палитре).
- **pass**, если ≤ 4.

**Фикс:** сократить число графиковых/акцентных цветов; держать 60-30-10.

### `headline:assertion` — заголовки-выводы (advisory)
Для каждого слайда, чей `type` не в `{title, divider, closing, cover, section}`,
заголовок должен быть **assertion headline** — полное предложение с глаголом
(вывод, а не тема). Эвристика (RU/EN): помечает заголовок, если ≤2 слов ИЛИ не
найден глагол (лексикон EN + суффиксные правила RU).
- **warn**, если есть тема-стиль заголовки. Не блокирует сборку.
- **pass**, если все проверенные заголовки — выводы.

**Фикс:** переписать «Выручка» → «Рост выручки ускорился до 40% в Q3».

### `density:words` — бюджет слов на слайд
Оценивает слова на слайд из `title` + `body` + `bullets`.
- Лимит: 60 (standard) / 120 (`strategy.density == "text-heavy"`).
- **warn**, если превышен. Не блокирует.
- **pass**, если в бюджете.

**Фикс:** разбить плотный слайд; перенести детали в приложение; правило 50/25/10.

### `consistency:mood` — единый mood на деку
Дека должна использовать один `theme.mood` (слайды могут переопределять, но
тогда должен совпадать).
- **fail**, если встречено >1 различных mood (включая переопределения в слайдах).
- **pass**, если mood один (или не задан).

**Фикс:** выбрать один mood, согласованный со смыслом и палитрой.

## Соответствие дизайн-системе

Правила взяты из `deck-html/references/design-system.md` и `product-designer.md`:
≤2 шрифта, ≤4 акцента, одна идея/слайд, WCAG ≥4.5:1 (текст) / ≥3:1 (крупный и
не-текст), assertion-заголовки, контент <60% площади, один radius/stroke на деку,
без эмодзи-иконок. `deck_audit` механически покрывает контраст, токены, бюджет
акцентов, заголовки-выводы, плотность и единство mood; остальное (плотность
визуальная, иконография) — за рамками статического чека.
