# GitHub Repo Hygiene — оформление и поддержание описательной части репозитория

Загружай этот скилл, когда нужно **оформить или проверить соответствие** описательной
части GitHub-страницы репозитория: README, лицензия, контрибьюшн-файлы, теги поиска,
ссылка на GitHub Pages.

## Цель

Чтобы страница репозитория на GitHub всегда отражала **актуальное состояние** проекта:
не отставала после мажорных изменений (новые сервисы, фичи, саги, смена стека) и была
полноценной (все обязательные разделы на месте).

## Обязательные файлы репозитория

| Файл | Назначение | Когда обновлять |
|------|-----------|-----------------|
| `README.md` | Англ. версия, главная страница | при любых мажорных изменениях |
| `README.ru.md` | Русская версия (зеркало англ.) | синхронизировать с англ. |
| `LICENSE` | MIT-лицензия (owner/year) | при создании, смене владельца |
| `CODE_OF_CONDUCT.md` | Contributor Covenant 2.1 | редко |
| `CONTRIBUTING.md` | Инструкция контрибьюторам | при смене процессов/конвенций |
| `SECURITY.md` | Политика безопасности | при смене контактов/политики |
| `.github/workflows/ci.yml` | CI | при изменении проверок |

## README — обязательные элементы

1. **Шапка**: название, однострочное описание проекта, значок-линки (badges).
2. **Статус-блок**: актуальные цифры проверок (typecheck/contract/integration).
3. **Быстрый старт**: установка, инфраструктура, запуск.
4. **Структура репозитория**: полное дерево (включая новые каталоги/сервисы).
5. **Разделы про стек/события/проверки** — синхронизировать с реальным кодом.
6. **Ссылка на GitHub Pages** (если включён): `https://<user>.github.io/<repo>/`.
7. **Языковая шапка-переключатель**: `**🌐 Versions:** [English](README.md) · [Русский](README.ru.md) · [Website](…)`.
8. **Хэштеги/ключевые слова** — для поиска (описание + topics).

### Правило двух версий

- `README.md` — **всегда на английском** (международный стандарт GitHub).
- `README.ru.md` — русская версия, **зеркало**: при изменении англ. версии
  переносить правки в русскую (структуру, цифры, статусы).
- Языковые блоки-переключатели в обеих версиях.

## Теги поиска (topics) и описание

Устанавливать через `gh api`:

```bash
# Описание репозитория
gh repo edit --description "<полное описание с ключевыми словами>"

# Теги (массив через -f 'names[]=...')
gh api -X PUT repos/<owner>/<repo>/topics \
  -f 'names[]=typescript' -f 'names[]=fastify' -f 'names[]=postgresql' \
  -f 'names[]=nats' -f 'names[]=microservices' -f 'names[]=event-driven' \
  -f 'names[]=monorepo' -f 'names[]=nodejs' -f 'names[]=backend'
```

Рекомендации по тегам:
- язык/фреймворк/БД/брокер (ключевые)
- архитектурные паттерны (`event-driven`, `microservices`, `event-sourcing`)
- тип проекта (`personal-os`, `pim`, `monorepo`)
- максимум 20 тегов (лимит GitHub)

## GitHub Pages

Если Pages включён (`gh api repos/<owner>/<repo>/pages`), в README обязательна
ссылка вида `https://<owner>.github.io/<repo>/`. Проверять, что ссылка рабочая.

## Чеклист проверки при мажорном изменении

Запускать при: новый сервис/фича/сага, смена стека, смена портов/схем, изменение
контрактов, изменение процессов (CI/коммиты), любой релиз/гейт.

1. [ ] `README.md` отражает новое состояние (структура, сервисы, цифры тестов, статус).
2. [ ] `README.ru.md` синхронизирован с англ. версией.
3. [ ] `LICENSE` на месте, owner/year корректны.
4. [ ] `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md` на месте и актуальны.
5. [ ] `gh repo edit --description` актуально (ключевые слова для поиска).
6. [ ] topics (`gh api .../topics`) актуальны и не превышают 20.
7. [ ] Ссылка на GitHub Pages в README рабочая.
8. [ ] CI-бейдж/статус в README соответствует реальному состоянию.
9. [ ] Коммит/пуш сделан, изменения видны на GitHub.

## Команды проверки

```bash
# Файлы на месте
ls LICENSE CODE_OF_CONDUCT.md CONTRIBUTING.md SECURITY.md README.md README.ru.md

# Описание + homepage
gh repo view --json description,homepageUrl

# Теги
gh api repos/<owner>/<repo>/topics

# Pages
gh api repos/<owner>/<repo>/pages
```

## Примечания

- README.ru.md — специфика этого проекта (ЦУП/PMOS); в других проектах может не быть
  русской версии — проверять наличие перед синхронизацией.
- Не менять `README.md` без явной просьбы, если он уже актуален — скилл для
  проверки/обновления, а не для «улучшательств».
- После изменения README: `git add README.md README.ru.md && git commit && git push`
  (только по запросу пользователя).
